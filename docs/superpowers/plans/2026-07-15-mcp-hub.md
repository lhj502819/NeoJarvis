# MCP-Hub — 对称 skills-hub 的 MCP 共用方案

> 日期:2026-07-15
> 参考:`docs/superpowers/specs/2026-07-14-desktop-jarvis-v0.3-client-server.md`
> 依赖:`desktop/agent/jarvis/skills-hub.ts` + `skill-prefs.ts`(对称参照)

## Goal

让 **Jarvis 自己 + 派给小弟** 都能使用用户本机 Claude Code 的 MCP —— 用户在 `~/.claude.json` 里配好的 chrome-devtools/context7/figma 等 MCP,Jarvis **零配置**就能用于:
1. **自己直接使用**(不派单也能操作浏览器、查文档等)
2. **派给小弟使用**(小弟需要浏览器工具时自动继承)

同时保留 Jarvis 自身的 MCP CRUD(DB 存)作为"Jarvis 自加"来源,和用户黑名单开关。

## 现状

**已具备**:
- Claude Agent SDK 支持 `options.mcpServers` 传入
- **Jarvis brain 层**(`desktop/agent/jarvis/llm.ts:36-39`)已经用 `buildUserMcpServers(userId)` 拿 MCP 并合并 `jarvis-system` 传给 SDK
- **派单主路径**(`desktop/agent/a2a/client.ts:178`)也用同一个 `buildUserMcpServers`
- `desktop/agent/shared/user-mcp.ts` → `buildUserMcpServers` 现在只从 DB 拉,**未接本机 hub**
- Java `/api/mcp-servers` 全 CRUD 端点齐(A2.5-4)

**缺失**:
- **本机 `~/.claude.json` 的 MCP 完全没接** —— 现在 Jarvis 和小弟都只能用 DB 里"Jarvis 自加"的 MCP
- `desktop/agent/team/factory.ts`(A2A server 执行路径)完全没接 MCP(次要,主路径已 OK)
- 无 UI 管理页
- recipe.tools 白名单未允许 `mcp__*`(SDK 会拒调)

**关键收敛点** —— 改 `buildUserMcpServers` 一处,Jarvis 和小弟同时受益(它们共用同一个函数)。

## 决策

**完全对称 skills-hub 的语义**:
- 扫描本机来源 → 加入 hub 池 → 与 DB "Jarvis 自加"合并 → 黑名单过滤 → 派单时 options.mcpServers

**与 skills 的差异**:
- MCP 不是文件夹,是 JSON 段,所以**不需要软链**,直接读文件
- 来源:`~/.claude.json` 的 `mcpServers`(用户级 Claude Code 配置)+ 未来可加 `~/.codex/config.toml` 的 mcp(先只做 Claude)
- **secret 感知**:mcpServers 里可能含 API key(env / args 里),不能落 Jarvis 日志、不能返回到未授权前端

## 交付

### 1. `desktop/agent/jarvis/mcp-hub.ts`(新)

**API 对称 skills-hub**:

```ts
export interface HubMcpServer {
  name: string
  type: 'stdio' | 'sse' | 'http' | 'ws'
  command?: string   // stdio
  args?: string[]    // stdio
  url?: string       // sse/http/ws
  env?: Record<string, string>
  source: 'personal' | 'builtin'   // personal = 本机 Claude 配的;builtin = Jarvis 内置(未来预留)
}

export function listHubMcpServers(): HubMcpServer[]
```

**实现**:
- 读 `~/.claude.json`(existsSync 保护,失败返空数组不抛)
- 取 `mcpServers` 段,每个 entry 变成 `HubMcpServer`
- source 一律 `'personal'`(本机 = 用户个人)
- 无副作用(不修改文件、不软链)

### 2. `desktop/agent/jarvis/mcp-prefs.ts`(新,对称 skill-prefs)

```ts
// 黑名单模型:表里有行 = 该用户禁用了这个 MCP
export async function getDisabledMcps(userId: string): Promise<Set<string>>
export async function setMcpEnabled(userId: string, name: string, enabled: boolean): Promise<void>

export interface McpView {
  name: string
  type: string
  source: 'personal' | 'builtin' | 'user'   // user = Jarvis DB 里自加的
  enabled: boolean
  // secret 感知:UI 用途,不返 env 明文,只标注哪些 key 需要 env
  envKeys?: string[]
}

// 给管理页用:合并 hub + DB user + 启禁状态
export async function listMcpsForUser(userId: string): Promise<McpView[]>

// 给派单用:启用的 MCP 完整配置(带解密 env),供 SDK options 用
export async function getEnabledMcps(userId: string): Promise<Record<string, McpServerConfig>>
```

底层 HTTP 端点:
- `GET /api/mcp/prefs`(返 {disabled: [name]})—— Java 新增
- `POST /api/mcp/{name}/toggle`(body {enabled}) —— Java 新增

**要点**:
- 类似 `PIPELINE_SKILLS`,可预留 `PIPELINE_MCPS = ['agent-comms']` 恒挂不受启禁
- `getEnabledMcps` 是给 client.ts 派单用的,返回结构直接对齐 SDK `options.mcpServers` 格式

### 3. `desktop/agent/shared/user-mcp.ts` 改造

`buildUserMcpServers(userId)` 已存在,现在改成:
- 拿 hub(本机):`listHubMcpServers()`
- 拿 DB user 自加:原有 `resolveMcpServers(userId)`
- 拿黑名单:`getDisabledMcps(userId)`
- **合并**:hub 与 user 同名冲突时,**user(DB)优先**(用户明确配的凭证覆盖本机默认)
- 过滤黑名单
- 排除 PIPELINE_MCPS(内部一定挂)
- 返回 SDK 需要的 `Record<string, McpServerConfig>` 结构

### 4. `desktop/agent/team/factory.ts` 补漏

L55 附近 `options` 加 `mcpServers: await buildUserMcpServers(userId)` —— 但 factory 是 A2A executor,没 userId(recipe 没带 user 上下文)。**决策**:factory 是 A2A server 执行路径,当前 recipe 表里没 user_id?看下再说,可能得在 startAgentServer 时把 userId 传进 executor。

### 5. Java 侧新增(小改)

- 新表 `jarvis_mcp_prefs`(user_id, mcp_name, PRIMARY KEY 复合)—— 完全对称 `jarvis_skill_prefs`
- 新端点:
  - `GET /api/mcp/prefs` → {disabled: []}
  - `POST /api/mcp/{name}/toggle` body {enabled}
- 保留现有 `/api/mcp-servers` CRUD(那是 DB user 自加的 CRUD)
- schema.sql 更新;service/mapper/controller/tests 全套

### 6. 前端 UI 管理页(对称 SkillsPage)

- `web/src/pages/dashboard/McpPage.tsx`(新)
- 复刻 SkillsPage 布局:tab(全部/本机/自加)+ 卡片(名称/类型/env keys 徽章/启禁 toggle)
- 侧栏加"MCP 服务器"入口
- API:`GET /api/mcp/hub`(TS 智能层扫本机返)+ `GET /api/mcp/prefs`(黑名单)+ `POST /api/mcp/{name}/toggle`
- **不显示明文 secret**(env values 全屏蔽,只显示 key)

### 7. Recipe.tools 白名单

现有 recipe 的 tools 数组可能没允许 `mcp__*`。SDK 里 allowedTools 支持 glob `'mcp__*'` 通配。**决策**:
- 内置 recipe 的 tools 白名单加 `mcp__*` 通配(晋升自动补,或统一改)
- adhoc(临时工)默认放开(与现在保持一致,他们本来就宽松)

## 安全边界

- `~/.claude.json` 里的 secret 走 SDK 到小弟进程,与"Jarvis 派本机 agent"的原有模式一致(agent 本来就在本机跑,能读用户所有文件)—— 语义可接受
- **不在**日志/UI/前端返回中打印 secret
- **不在** Java DB 里存本机 hub 的 secret(hub 只在 TS 智能层内存里流转)
- 前端只看到 envKeys 列表(不是 value)
