# v0.3 Plan A2.5 + Plan C + Plan B —— 完整落地实施计划

> **For agentic workers:** REQUIRED SUB-SKILL: `superpowers:subagent-driven-development`。步骤用 checkbox 跟踪。server 侧遵守 `server/CLAUDE.md`。
> 前置:Plan A(A0-A4)已完成——Java server 有 17 表 + 读 CRUD + 多用户认证,139 测试绿,本地连 MySQL 跑通。

## 背景与真实规模

Plan A 的 A2/A3 主要建了**读端点**。但老 TS 智能层(`src/`)有大量**写操作**没有 Java 端点。完整 v0.3 = 让 Electron 主进程跑智能层、数据 CRUD 全调 Java。因此需要三阶段:

1. **A2.5**:Java 补齐智能层需要的写端点(~30 个)
2. **Plan C**:老 TS 16 文件的数据层「保签名、换底层」——`pool.query` → 调 Java HTTP
3. **Plan B**:Electron 壳(main/preload/window/打包),主进程跑智能层

## 全局约束

- server 侧:守 `server/CLAUDE.md`(分层、构造器注入、MyBatis 注解、显式列名 SELECT、AssertJ)
- TS 侧:**保持所有数据层函数签名不变**(上层 brain/routes/tools 零改动),只换函数体
- 字段 camelCase 对齐;路径与老 TS 对齐(见下方契约差异修正)
- 老 TS 改造在 `feat/v0.3-server-extract` 分支;改造中途老 TS 可能半可跑,以 Java 为准
- 每阶段 `mvn test`(server)+ `npx tsc --noEmit`(TS)通过

## 已知契约差异(Plan C 要对齐)

## 阶段二:Plan C —— TS 数据层换底层调 Java

### C-0:HTTP client 基础设施

新建 `src/shared/server-client.ts`:
- `serverGet<T>(path)`、`serverPost<T>(path, body)`、`serverPatch`、`serverDelete`
- baseURL 来自 env `JARVIS_SERVER_URL`(默认 `http://localhost:8080`)
- 带认证:内部服务调用用 service token(或 dev 模式 header `X-User-Id`)—— **关键**:TS 数据层函数都接收 `userId` 参数,HTTP 调用要把 userId 传给 Java。方案:请求头 `X-Internal-User: {userId}`,Java 端 dev-bypass filter 认这个头注入 userId(A4 filter 补一个分支)
- 错误处理:非 2xx 抛异常,保持与老 TS 一致的失败语义

### C-1 ~ C-N:逐文件换底层(保签名)

按依赖顺序,每个文件把 `pool.query(...)` 换成 `serverGet/Post/...`,**函数签名和返回类型一字不改**:

| C-1 | src/jarvis/state.ts | /api/state | 最简单,先做验证模式 |
| C-2 | src/team/registry.ts | /api/recipes* | |

### C-认证衔接

老 TS 的 `authMiddleware`(cookie JWT)在 Electron 单机下要不要保留?
- **决策**:Electron 主进程内部调用带 `X-Internal-User`,不走 cookie。routes/ 层(如果 Electron 仍用 HTTP 而非 IPC)保留 cookie 校验。**Plan B 决定 IPC vs HTTP 后再定**。

## 阶段三:Plan B —— Electron 壳

### B-1:Electron 骨架
- `desktop/` 目录:package.json、main/index.ts、preload/index.ts
- 主进程:启动时 spawn/require 老 TS 智能层(现在改调 Java 数据层)
- BrowserWindow 加载 web/(dev 指 vite 5180,prod 指打包的 dist)
- 窗口/托盘基础

### B-2:主进程接智能层
- 主进程 `require` 老 TS 的 brain/orchestrator/agent(数据已走 Java)
- 渲染进程 ↔ 主进程:先用 HTTP(主进程内起 express,复用 routes/),或改 IPC——**B-1 时决策**
- 环境变量注入:`JARVIS_SERVER_URL=http://localhost:8080`、BYOK from keychain

### B-3:打包
- electron-builder,macOS dmg
- Java server 怎么随 app?**决策**:v0.3 本地阶段 Java 单独跑(用户手动起 or 脚本),Electron 只管客户端。CloudBase 部署后 Electron 连云端,不打包 Java。
