## 1. 表结构改动必须先确认

只要涉及数据库结构——新建表、加/删字段、改字段类型、加索引、改主键、数据迁移、分库分表、加约束——都必须：

1. 先给出变更方案：表名、字段、类型、默认值、是否可空、兼容策略、影响面（谁读谁写）、上线与回滚步骤；
2. 通过 message_jarvis 上报方案，Jarvis 转给 Sir，等 Sir 明确回复「同意 / 可以 / 按这个来」；
3. 收到确认之前，不写 migration、不改实体类、不动 DDL，也不要在方案里顺手把代码改了。

只读查询、写测试数据的临时脚本不算改结构，但也要在方案里说明。

## 2. 线上问题先查日志，不要直接读代码

任务描述里是线上/预发已经发生的问题（报错、超时、数据不对、页面白屏）时，第一步不是打开 IDE，而是查那个环境当时的日志：

1. 环境三要素不全时，通过 message_jarvis 让 Jarvis 去问：环境（prod / pre2 / 预发）、时间点或时间范围、现象（报错文案、哪个接口、哪位用户/哪个单号）。
2. 进对应仓库，用该仓库自带的查日志技能（不是全局技能）：
   - one-decision/.claude/skills/log-search/（应用 one-server / one-jds-server，走 dongmonitor）
   - one-decision/.claude/skills/log-query-skill/（只知道容器 IP 时用）
   - uniops-server/.claude/skills/log-search/（应用 uniops-server）
3. 从日志里拿到类名、异常栈、traceId/reqId、接口路径、耗时之后，再去代码里定位到具体那一行。

日志能直接指到类和方法时，就不要靠读代码猜。只有日志拿不到时，才退回到读代码 + 复现。

## 3. 读代码或动代码之前，先拉一份干净的最新代码

不要直接在现成的本地克隆上排查——它可能在旧分支、有未提交改动、或者根本不是最新代码。凡是任务需要读代码或改代码：

**先判断是接续任务还是全新任务：**

- **接续任务**（任务描述或历史记忆里给了上次的工作目录 / 分支 / commit，且本次要在此基础上继续）→ **直接进那个目录接着干**，先 `git status -sb` 和 `git log --oneline -3` 确认现场还在、分支没被覆盖，然后继续。**不要重新 clone**——clone 会丢掉上次的未提交改动、本地分支和 commit，等于把上游成果清零。
- **全新任务**（没有明确的现场信息）→ 按下面流程新建干净目录：

1. 在工作区里新建独立目录：<工作区根>/<任务短名>/（短名能看出是哪件事）；
2. 从业务分工里的仓库地址 clone 最新代码；已有干净克隆时 git fetch 后切默认分支再 git pull；
3. 在该目录里排查/开发，改动提交到独立分支，不直接推主分支；
4. 仓库自带的 .claude/skills（含查日志技能）在克隆目录里同样可用。

已有目录里有别人的未提交改动时，不要 reset 或覆盖，另开一个目录。

## 4. 代码改动必须先出方案，同意后才能写

任何代码改动（包括「就改一行」）都先出方案，方案至少包含：

- 问题定位：哪一行/哪个类/哪条链路出的问题，怎么确认的；
- 改动点：要改哪些文件、大致怎么改；
- 影响面：谁在调用、会不会影响别的场景；
- 验证方式：怎么证明改对了（编译/单测/接口自测/复现步骤）；
- 风险与回滚：最坏情况是什么，怎么退回去。

方案通过 message_jarvis 上报，然后停下来等——确认会经 Jarvis 回到你的收件箱。没有拿到明确的同意（「可以」「同意」「按这个做」），不创建分支、不改文件。被否掉就改方案，不要换个说法强推。

## 5. 部署：先用仓库自带的部署技能

需要部署/上线时，先看这个仓库有没有部署技能，有就照它执行；没有就通过 message_jarvis 问，不要自己拼 JDOS / pubfree 的命令。

| 仓库 | 技能 | 覆盖范围 |
| --- | --- | --- |
| one-decision | .claude/skills/one-deploy/ | 后端 one-decision（one-server）→ JDOS 预发 / 生产 |
| one-decision | .claude/skills/fe-deploy/ | 前端 oxygen-one → pubfree（云构建 + 上线） |
| one-workbench | .claude/skills/fe-deploy/ | 前端 → pubfree |
| uniops-server | .claude/skills/uniops-deploy/ | uniops-server → JDOS 预发（只做预发） |
| uniops-ui | 无部署技能 | 到这儿先停下来问，不要自创流程 |

几条规矩：

- 这些是仓库级技能，agent 的 cwd 是工作区根，不会被自动加载——先 Read <repo>/.claude/skills/.../SKILL.md，按里面的步骤执行。
- 生产环境一律人工：技能只做预发就只做预发，不要绕过脚本层的拦截。
- 部署前先按第 4 条出方案，写清楚部署哪个分支、哪个环境、回滚怎么做，等确认。
- 部署完把结果（环境、版本、时间、日志链接）写进汇报。
